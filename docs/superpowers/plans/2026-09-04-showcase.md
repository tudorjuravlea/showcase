# Showcase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Headless CLI + Claude skill producing cinematic device-mockup MP4s and self-contained hero HTML from a screen recording or image.

**Architecture:** Extends the WebGL renderer with a camera rig + external screen source; pure choreography module maps t→{pose,camera}; a showcase page exposes a deterministic seek API for the Playwright+ffmpeg CLI and a live float/hover mode for HTML export; ffmpeg-based activity analysis feeds the auto-action look.

**Tech Stack:** existing repo (Vite, Three.js, Playwright, Vitest) + system ffmpeg/ffprobe. NO new deps.

**Spec:** docs/superpowers/specs/2026-09-04-showcase-design.md (binding, incl. Economy constraints)

## Global Constraints

- No new npm deps; no React outside src/app; editor behavior unchanged (all existing suites stay green).
- Exact interfaces below are contracts between tasks — names verbatim.
- Fixture: create e2e/fixtures/showcase-sample.mp4 (≈4s, ≤2MB, re-encoded trim of a local reference screen recording). Task 1 creates it; later tasks reuse it. *Superseded 2026-09-06: the committed fixture is fully synthetic (ffmpeg lavfi) — see e2e/fixtures/README.md.*
- Suites green before each commit (npm test / npm run e2e / npm run lint / npm run build).

### Task 1: Renderer extensions + fixture

**Files:** Modify src/render/webgl/glRenderer.js; create e2e/fixtures/showcase-sample.mp4 (originally an ffmpeg trim/re-encode of the reference .mov; since replaced by a fully synthetic clip — see e2e/fixtures/README.md); add tests to tests/glrenderer.test.js.

**Interfaces produced:**
- `setCamera({distance, targetU, targetV, driftX, driftY})` on the renderer handle — distance multiplies default framing distance (1 = current view, 0.35 ≈ close-up); targetU/V (0..1) aim position+lookAt at that point of the screen plane; drift small world offsets. Callable per-frame like setPose.
- `setScreenSource(canvasEl)` + `updateScreen()` — external canvas becomes the screen CanvasTexture (SRGB); updateScreen sets needsUpdate + renders. Works for all devices incl. browser (chrome bar composed OVER the source: reuse composeChromeTexture with the canvas as image input if cheap, else draw content full-bleed for browser too — implementer's call, note it).
- `scene.style.scene === "showcase"` → black background, stronger key/rim lighting, boosted screen emissive, contact shadow kept. Default scene untouched.

**Steps:**
- [ ] Create the fixture with ffmpeg; commit it (small).
- [ ] Implement setCamera; unit-test the pure math (exported `cameraLayout(cam, layout)` → position/lookAt numbers; assert distance scaling + UV targeting move as expected).
- [ ] Implement setScreenSource/updateScreen; unit-test contract shape under jsdom (methods exist; no-throw pre-render).
- [ ] Implement showcase scene style; e2e-light check: none (visual judged later). Keep matrix untouched.
- [ ] Suites green; commit "feat: camera rig, external screen source, showcase scene".

### Task 2: Looks + runtime page

**Files:** Create src/showcase/looks.js, src/showcase/runtime.js, showcase.html, tests/looks.test.js. Modify vite config only as needed to add the entry.

**Interfaces produced:**
- `lookFrame(name, t, ctx) => {pose, camera}`; `LOOKS` keys exactly: hero-drift, close-up-pan, orbit-loop, flat-lay-rise, hero-rise, auto-action. ctx = {duration, activity: [{t0,t1,u,v,zoom}]|[]}. All values finite for t∈[0,1]; orbit-loop frame(0)≈frame(1); auto-action with empty activity === hero-drift.
- `window.__showcase.init(cfg)` (cfg: {device, orientation, look, content:{kind:"video"|"image", url}, duration, width, height}) → Promise (renderer ready, first frame drawn); `window.__showcase.seek(t)` → Promise after the content frame at t*contentDuration (looped) is on the screen texture AND the GL frame rendered. Content video muted+preload; seek via 'seeked' event (rVFC if trivial).
- Live mode: `init` with cfg.live=true plays the look once (duration), then idles: float loop + hover-follow (pointer eases rotateX/Y ±6° spring-smoothed; no pointer = float only).

**Steps:**
- [ ] TDD looks (keyframe assertions per look: hero-rise starts below frame → translateY large positive at t=0; close-up-pan camera.distance small at t=0, ≈1 at t=1; orbit loop closure; auto-action targets segment u,v during its window).
- [ ] Runtime page + headless API; manual check with vite dev (screenshot yourself, save to SDD screenshots dir: fixture video on phone, showcase scene, mid-look — must look dark/cinematic, content sharp).
- [ ] Suites green; commit "feat: showcase looks + runtime page".
